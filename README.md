# FitDiary — практическое обучение, вариант 9

Репозиторий для проверки преподавателем: [TrenCteatine/fitdiary-practice](https://github.com/TrenCteatine/fitdiary-practice).

Настольный фитнес-трекер: дневники питания и тренировок, расчет КБЖУ порций, ИМТ, шкала дневной цели и фоновая статистика. Python 3.11+, Tkinter, стандартная библиотека. Проверено на Windows 11, Python 3.13.1.

## Быстрый запуск

Откройте `release/FitDiary.exe`. Установка Python для готовой Windows-версии не требуется. Данные создаются при первом сохранении в `%LOCALAPPDATA%/FitDiary/diary.json`. Не запускайте одновременно два экземпляра с одной папкой данных.

Для демонстрации откройте `Демонстрация.cmd`. Она использует отдельный дневник `demo-data` рядом с проектом. Демонстрационные значения продуктов иллюстрируют работу приложения.

Из исходников:

```powershell
python -m fitdiary
python -m fitdiary --demo --data-dir demo-data
```

Калорийность и БЖУ вводятся **на 100 г**, масса — для съеденной порции. Программа умножает каждое значение на массу / 100. Рост задается в сантиметрах, масса тела — в килограммах. ИМТ = масса / (рост / 100)². Дневная цель задается пользователем. Калории тренировок показываются отдельно от питания.

## Состав комплекта

- `release/FitDiary.exe` — собранное приложение Windows x64.
- `fitdiary/`, `run.py` — полный исходный код.
- `tests/` — модульные, изолированные и интеграционные тесты.
- `docs/Отчет по практике.docx` — пояснительная записка, автоматическое содержание, UML, макеты, результаты проверок и приложения с кодом и снимками.
- `docs/Руководство пользователя.docx` — запуск, операции, сообщения, резервные копии.
- `docs/Руководство программиста.docx` — архитектура, проверка, сборка, формат данных и ограничения.
- `docs/Календарный план и материалы по дням.docx` — план на 20 учебных дней и указатели на результаты каждого этапа.
- `docs/api/index.html` — автоматически сформированный справочник API.
- `docs/diagrams/` — изображения UML и макетов, редактируемые исходники PlantUML.
- `docs/Защита.md` — последовательность демонстрации и ответы на вопросы.
- `evidence/` — исходные результаты тестов, покрытия, профилирования, отладки и снимки работающей программы.

На титульных листах заполните поля в квадратных скобках. Подписи и фактические даты практики заполняет студент. Календарь построен по 20 будним дням с 12.10.2026, без учета возможных переносов колледжа; это план, а не подтверждение посещения или выполнения в прошлые даты. Образец титульного листа колледжа имеет приоритет.

## Проверка и сборка

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe tools\verify.py
.\.venv\Scripts\python.exe tools\benchmark.py
.\.venv\Scripts\python.exe -m PyInstaller --onefile --windowed --name FitDiary --distpath release run.py
```

Тесты используют `unittest` и `unittest.mock` вместо pytest/Moq. Требуется доступный графический сеанс для тестов Tkinter. Покрытие измеряется по всем модулям `fitdiary`, включая интерфейс и точку входа; это покрытие строк, не ветвей. Сохраненный результат: 67 тестов, 470 из 471 исполняемых строк (99,79%). Сохраненные результаты относятся к конкретной проверенной сборке; после изменений запустите проверку заново.

Статистика рассчитывается в `ThreadPoolExecutor`; результаты передаются в Tk через опрос `after`. Это альтернатива `async/await`. Поток не дает гарантии параллельного выполнения Python-кода на нескольких ядрах, но отделяет расчет от обработчика интерфейса. Сохранение JSON остается синхронным; на 55 000 записей оно может занимать около секунды. Интерфейс показывает до 500 строк выбранного дня/статистики, при этом итоговые расчеты учитывают все записи.

## Резервное копирование

Кнопка «Резервная копия» сохраняет JSON в выбранный файл. Для восстановления закройте приложение, сохраните текущий `diary.json` отдельно и скопируйте нужную копию на его место. Для проверки копии без изменения рабочего дневника используйте `--data-dir другая-папка`. Поврежденный файл при запуске вызывает сообщение об ошибке и не заменяется пустым.

## Ограничения

Один пользователь, один локальный дневник, без учетных записей, синхронизации, базы продуктов и автоматического назначения рациона. Корректность питания зависит от введенных значений. Снимки и нагрузочные записи демонстрационные. Программа не выполняет медицинскую интерпретацию ИМТ.
